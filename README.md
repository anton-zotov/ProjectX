# ProjectX

Мини-игра на canvas: надпись **Hello, World!**, которой управляют стрелками,
летает по большому игровому полю на фоне самосветящейся псевдо-3D решётки.

## Запуск

Для разработки (горячая перезагрузка):

```bash
npm install
npm run dev        # http://127.0.0.1:5173
```

## Проверки и релиз

Тесты и проверка типов — отдельные команды: **во время игры они не выполняются**
и на неё не влияют. Запускайте их перед релизом:

```bash
npm run preflight  # typecheck + тесты + production-сборка
npm test           # только автотесты (34 штуки, без внешних зависимостей)
npm run typecheck  # только проверка типов
```

Поиграть в собранную версию (легче для машины: без dev-сервера, вотчера и HMR):

```bash
npm run build
npm run serve      # отдаёт dist/ на http://127.0.0.1:5173
```

## Что внутри

Игра — продвинутая копия **Ragdoll Masters**: по арене летают тряпичные
человечки («чувачки»), игрок управляет только вектором тяги. Полное описание
замысла, геймплея и планов — в **[docs/VISION.md](docs/VISION.md)**;
консолидированная сводка проекта (что сделано, где успех, что не получилось) —
в **[docs/SUMMARY.md](docs/SUMMARY.md)**.

> ## ⚠️ Главное правило проекта: физика общая и универсальная
>
> Какого бы результата мы ни добивались, механизм обязан работать **одинаково
> везде и для всех**: одни и те же законы и симметрии, никаких правил «а вот
> здесь поведение другое». Хотим, чтобы чувачок стоял на земле, — **не смеем**
> учитывать его близость к земле: мы обязаны придумать такую физику, из которой
> стояние следует само. Подгонять поведение объекта под окружение запрещено.
>
> **Проверка перед каждым изменением:** механизм знает, где пол, стена или
> другой игрок? Если да — это подгонка, а не физика.
>
> Так был **отвергнут** вариант «мышцы работают, только пока ноги у пола», а
> вместо него принято **сцепление суставов** — трение в сочленении, которое
> работает одинаково и на земле, и в невесомости, и вверх ногами. Страж правила
> живёт в тестах: *«the physics does not know where the floor is»* — один и тот
> же сценарий у пола и высоко в воздухе обязан дать одинаковый кадр (проверено:
> с привязкой к полу расходятся на 39 px и три теста падают).

- **Чувачок** — скелет из 16 точек (голова, корпус, руки, ноги), связанных
  костями; считается методом PBD/Verlet с фиксированным шагом 1/60 с.
  Тяга прикладывается **в голове**, поэтому тело само закручивается и
  кувыркается; есть инерция (в невесомости), низкая гравитация и упругие
  столкновения со всеми четырьмя стенами арены.
  Пока тело **сплошное белое, без контура**, голова сделана маленькой (это
  главная цель для ударов), а сочленения есть только в шее, плечах и тазу —
  локти и колени жёсткие. Едва заметные глаза нужны, чтобы читалась
  ориентация тела.
- **Поле** — 3×2 экрана (960×360), камера следует за головой и может
  заглядывать за края карты; за границей зоны — «стена» (лист с прямоугольной
  дыркой), сквозь которую видно трёхмерное пространство.
- **3D-пространство** — уровни глубины (поперечные линии) плюс «лучи»,
  уходящие вдаль; яркость и толщина зависят от глубины, совпадающие линии
  не складываются в сверхъяркие, лучи плавно появляются/гаснут у края экрана.
- **Цвета фона** — переливаются сами (две дрейфующие синусоиды), скорость
  регулируется.
- **Управление** — стрелки дают вектор тяги. По умолчанию включён
  «авто-пилот»: чувачок летает сам (демо), снимите галочку и управляйте вручную.
- **Админка** — кнопка ⚙ справа сверху: тяга, гравитация, авто-пилот,
  скорость цвета, размер поля, размер ячейки фона, вкл/выкл 3D-сетки,
  сглаживание 2× (снять — самый быстрый способ поднять FPS: буфер становится
  1×, растеризация вчетверо дешевле) и профилирование.
  После правки фокус возвращается в игру, чтобы стрелки сразу управляли телом.
- **FPS** — счётчик в левом верхнем углу: `fps 60  16.7 ms` (ограничен частотой
  обновления монитора: на 60 Гц больше 60 не покажет). Галочка
  «профилирование» добавляет строку `upd X ms · draw Y ms`, чтобы понять, что
  именно стоит кадров — логика или отрисовка.

## Структура

```
docs/
  VISION.md             вводные и дорожная карта проекта (читать перед этапом)
src/
  main.ts               точка входа + админка (DOM) + отладочный хук __projectx
  engine.ts             цикл кадров, canvas, масштабирование (буфер 2x)
  scene.ts              интерфейсы Scene / GameContext
  input.ts              состояние клавиатуры (isDown / axis)
  game/config.ts        параметры физики и тела (шаг, гравитация, тяга…)
  game/ragdoll.ts       скелет чувачка: точки, кости, решатель, столкновения
  scenes/arena.ts       арена: фиксированный шаг, камера, отрисовка, админ-настройки
tests/
  helpers.mjs           подставные canvas/DOM, чтение нарисованного
  loader.mjs            ESM-хук: расширения + заглушка для .css
  ragdoll.test.mjs      физика: гравитация, тяга, инерция, детерминизм, кости
  arena.test.mjs        арена: камера, поле, стены, рендер, сетка, fps
  input.test.mjs        клавиатура
  app.test.mjs          движок (кадры, ресайз, dt) + админка
versions/               локальные снапшоты версий (см. versions/README.md)
```

## Тесты

Тесты используют встроенный раннер Node и импортируют TypeScript напрямую
(Node стирает типы, `tests/loader.mjs` добавляет расширения) — никаких
тест-фреймворков и сборки. Физика проверяется напрямую (детерминизм, длины
костей, границы поля), отрисовка — через подставной canvas-контекст, который
записывает все вызовы.
