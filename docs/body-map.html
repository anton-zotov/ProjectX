Как устроен чувачок в коде

Схема ниже нарисована из живых данных: скрипт создаёт настоящий объект Ragdoll и рисует его кружки, кости и суставы. Если завтра скелет поменяется — картинка поменяется вместе с ним (перезапустить node devtools/body-map.mjs).

1. Модель чувачка — это ОДИН класс

Всё, что описывает тело, живёт в src/game/ragdoll.ts: класс Ragdoll и три маленьких интерфейса-описания (Circle — кружок, Link — связь, Bone — кость). Больше про чувачка не знает никто: сцена умеет только вызвать step() и нарисовать то, что лежит в объекте.

Стрелки: числа из config.ts попадают в Ragdoll; сцена дёргает его шаг и рисует результат; цикл кадров — в Engine.

2. Из чего состоит живой объект Ragdoll

СОСТОЯНИЕ (меняется каждый кадр)

полечто это
points[]кружки: x, y, px, py (Верле), im (обратная масса), r, part
links[]связи: какие два кружка, rest/min/max, податливость, joint?
drawn[]те связи, которые рисуются капсулами
bones[]кости: списки кружков, которые держатся прямыми
contacts[]пары несвязанных кружков, которые расталкиваются
hits, lambda, simTimeрабочие переменные решателя

Всё это создаётся в конструкторе и живёт только в памяти вкладки.

СХЕМА (то, что мы правим)

гдечто
CHAINSцепочки: голова, тело, руки, ноги — сколько кружков, под каким углом, куда крепятся, где шарнир
TORSO_COUNT, углы, шагиконстанты сборки скелета
config.tsвсе числа физики: жёсткости, пределы, тяга, гравитация

Это обычные константы в исходнике (не данные и не сериализованный объект). Меняем схему — правим код и пересобираем.

3. Скелет, как он собран сейчас

head: 1 · torso: 5 · armL: 4 · armR: 4 · legL: 5 · legR: 5 — всего 24 кружков
звено цепочки (капсула: то, что видно) кость (кружки, которые держатся прямыми) сустав-связь (держит угол: сцепление)

4. Как схема хранится и почему это важно

Сейчас: схема — это код. Цепочки описаны константой CHAINS прямо в модуле ragdoll.ts, числа — константами рядом, физика — в config.ts. Из них конструктор собирает объекты в памяти. Ничего не сериализуется: ни в файл, ни в localStorage — игра всегда строит чувачка заново из кода.

вопроссейчасесли сделать схему данными
поменять количество кружковправка кода + пересборкаправка JSON
сравнить две схемыдве сборки, два портапереключатель в админке
«откатить» неудачную схемучерез снапшоты папоквернуть прежний JSON
дать поиграться тебетолько через меняправишь данные — видишь результат

Как это могло бы выглядеть (тот же конструктор, но схема приходит объектом — его можно положить в файл, в админку или в localStorage): 

{
  "id": "normal-24",
  "circles": { "body": 4, "headScale": 1.8 },
  "chains": [
    { "part": "head",  "at": [[0, 0]] },
    { "part": "torso", "from": "neck", "step": 8, "count": 5, "flex": false },
    { "part": "arm",   "attachTo": "torso0", "attachAngle": 45,
      "angle": 40, "step": 8, "count": 4, "hinge": 1 },
    { "part": "leg",   "attachTo": "torso4", "attachAngle": 36,
      "angle": 14, "step": 8, "count": 5, "hinge": 2 }
  ]
}

Класс Ragdoll при этом почти не меняется: он и сейчас уже принимает схему как данные (CHAINS) — надо только вынести её из модуля наружу и разрешить выбирать. Это, судя по вопросу, и есть то, чего не хватает: мы каждый раз правим скелет в коде физики, хотя это чистые данные.
